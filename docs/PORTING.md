# Windows-only code inventory for the Linux port

This inventory records Windows-specific code and Windows distribution assumptions found in
`apps/`, `core/`, and `tools/`. It is based on the checked-in source and build/package
scripts; it does not imply that a suggested alternative is already implemented.

Line numbers refer to the source as inspected for this inventory and may shift as files
change. API groups list every relevant occurrence or the enclosing implementation range.

## Summary

| Area | Windows-specific implementation | Linux status |
|---|---|---|
| Core file operations and autosave locks | Win32 replace/create/delete and process/time APIs | Portable branches already exist in `file_io.cpp` and `autosave.cpp`. |
| Crash reports | Windows SEH, module and file APIs; `%LOCALAPPDATA%` path | No Linux crash-report implementation; non-Windows functions are stubs. |
| GUI and workers | Windows process containment, resource limits, memory and GPU telemetry | Smart Quad has a partial non-Windows branch; TRELLIS, SAM and Retopo do not have functional Linux implementations. |
| Agent and chat | Win32 process launching, job control, DXGI/NVML, WinHTTP, wide entry points | Agent and chat targets are gated to Windows; no Linux implementation is present in these sources. |
| CLI/MCP and ZIP reading | Windows UTF-16 argv, console, descriptor and file APIs | CLI, MCP, path-policy, ZIP-open and environment-setting alternatives exist in conditional branches. |
| Updater and launcher | Win32 launcher, process creation and installer/update flow | Automatic update launch and the launcher/updater have no Linux implementation. |
| Build and distribution | PowerShell, MinGW/Windows Qt, `.exe`/`.dll`, Inno Setup | The reviewed scripts and package format are Windows-specific; no Linux package workflow is provided there. |

## Conditional-compilation and porting notes

- The portable branches that are already implemented are:
  - `core/pixel3d/engine/autosave.cpp`: POSIX time, PID and lock-file operations.
  - `core/pixel3d/common/file_io.cpp`: `std::filesystem::rename`.
  - `apps/cli/main.cpp` and `apps/mcp/main.cpp`: non-Windows argument/stdio/time handling.
  - `apps/mcp/args.cpp`: Windows-only path folding is omitted on Linux.
  - `apps/update/model_store.cpp` and `apps/update/update_service.cpp`: non-Windows `fopen` for ZIP files.
  - `tools/trellis/post_geometry_preview4.cpp`: non-Windows `setenv`.
- Several conditional branches are placeholders rather than ported behavior: crash reporting, SAM loading, TRELLIS RAM/GPU reporting and worker containment, and Retopo processing.
- `apps/backends/regional_fix_cli.cpp` is an exception to the guarded worker pattern: it includes Windows headers and calls `CommandLineToArgvW` without an `_WIN32` conditional.
- Qt `QSettings` appears in the application, but direct Windows Registry APIs such as `RegOpenKey`/`RegSetValue` were not found. The `QSettings::NativeFormat` usage noted in the summary table is an indirect platform-native backend, not a direct Registry API call.
- Windows SDK headers, linker libraries, `.exe`/`.dll` names, Windows-specific vendor binaries and package scripts are separate porting tasks from replacing API calls; all must be addressed for a Linux release.
